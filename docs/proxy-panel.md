# Панель сервера-прокладки

## Что есть в текущем проекте

`install.sh` устанавливает VPN-сервер и одну веб-панель на одном VPS. Отдельного установщика и панели для сервера-прокладки здесь нет. `forward_proxy` внутри Caddy относится к NaiveProxy на VPN-сервере.

## Схема из прежних проектов

В `vpn-proxy-installer` и `vpn-panel-5x-uev-unified` прокладка — отдельный VPS с OpenVPN, прокси-клиентами и балансировщиком. Пользователь подключается к OpenVPN на прокладке; исходящее соединение прокладки идёт к основному VPN-серверу через работающий прокси-протокол. В `unified` VPN-панель обращалась к API прокладки по адресу, порту и токену. Это целевая схема, подтверждённая владельцем проекта.

## Целевой путь установки

1. Установить основную панель на первом VPS.
2. Установить панель прокладки на втором VPS. Установщик показывает одну строку подключения.
3. Вставить строку в основную панель. Она проверяет прокладку, создаёт отдельный служебный профиль и передаёт параметры подключения.
4. Создать пользовательский профиль по названию. Панель сразу показывает готовый способ подключения. После создания можно открыть настройки конкретного протокола.

Поля UUID, SNI, пароль обфускации, путь xHTTP и ключ Reality не должны вводиться вручную при обычной связке.

## Требования перед выпуском

- Проверять сертификат или закреплённый ключ API прокладки. Не переходить на HTTP при ошибке TLS.
- Передавать API-токен в заголовке, не в URL. Дать возможность заменить токен и отвязать сервер.
- Служебный профиль прокладки отделить от профилей пользователей.
- Проверять применение конфигурации и возвращать понятную ошибку, если служба не запустилась.
- Проверять доступность каждого настроенного канала; при сбое активного канала переключаться на другой работающий и показывать в обеих панелях выбранный протокол и причину отказа.
- Если ни один канал не работает, блокировать выход клиентов в интернет через обычное соединение прокладки. Нельзя незаметно обходить основной VPN-сервер.
- Проверить TCP, DNS и UDP отдельно. Старый балансировщик направлял через прокси только TCP, а обычный UDP отклонял.
- Проверить установку, повторный запуск, связку, создание профиля, отключение и восстановление после перезагрузки на двух чистых VPS.

Код прежних проектов служит примером схемы. Он не должен переноситься без проверки безопасности и сетевого поведения.
